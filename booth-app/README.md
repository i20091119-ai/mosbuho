# 알고리즘으로 잠그고 수학으로 푸는 비밀 팔찌 — 부스 체험 앱

경상남도교육청 **경남수학문화관**이 **2026 경남직업교육박람회 미래기술 체험존**에서 운영하는
모스부호 기반 phygital(디지털↔실물) 체험 부스 앱입니다. 박람회 종료 후 수학문화관 상설 전시로도
사용하도록 견고하게 설계했습니다.

- **하드웨어**: Arduino UNO Q 1대(테이블당) + USB‑C PD 허브 + 포터블 모니터(USB‑C/mini‑HDMI, 10점 터치)
  + USB 웹캠 + 거치대/조명/라이트박스 + 부저 + **불빛 아케이드 버튼(물리 전신키)** + 소형 스피커
  - 배선·핀 배치는 [`arduino/README.md`](arduino/README.md) 참고 (버튼=D3, 버튼LED=D4, 부저=D2)
  - 입력 분담: **모스 누르기 = 아케이드 버튼**, 보기 선택·페이지 넘김 = **터치**
  - 버튼 LED가 12V면 **ULN2003(또는 트랜지스터) + 12V 어댑터**로 D4 스위칭(공통 GND)

## 개발 / 테스트 (보드 없이 PC·폰에서)

UNO Q는 최종 배포 대상일 뿐, **개발·수정은 PC 브라우저에서** 하고 보드엔 마지막에 한 번 올립니다.

- **로컬 미리보기**: `cd booth-app && python3 -m http.server 8000` → 크롬 `http://localhost:8000`
  (학년·스토리·미션·전신키·카메라·소리·통계 전부 동작. 전신키는 **스페이스바**, ⑦은 시뮬레이션)
- **개발 시뮬 모드**: URL 뒤에 **`?dev=1`** → 우하단 DEV 패널
  (화면 빠른 이동, 아케이드 버튼 누름/뗌 시뮬, 보드로 나갈 `play_morse` 명령 로그). 프로덕션엔 영향 없음.
- **폰/원격 테스트(선택)**: `.github/workflows/pages.yml` 로 GitHub Pages 자동 배포.
  저장소 **Settings → Pages → Source = "GitHub Actions"** 1회 설정 후 push 하면 테스트 URL 발행
  (HTTPS라 카메라도 동작). 부스 본운영은 그대로 UNO Q 오프라인.
- **단일 정적 웹앱** — UNO Q의 Linux(Chromium)에서 **로컬 구동**
- **완전 오프라인 · 외부 요청 0** — 폰트·차트·로직 전부 로컬. 인터넷 없이 동작
  (외부 CDN/원격 라이브러리 의존 없음)

## 체험 흐름 (세계관: 학생=우주통신사 · 해독=복호화, 응답=암호화)

| 단계 | 화면 | 내용 |
|---|---|---|
| ① 학년 선택 | `학년` | 유아·초등저(숫자) / 초등고(영문) / 중·고(한글) 3분기 |
| ② 이야기 | `이야기` | 그림책 4장면 (도입→신호) — 학년별 스토리 |
| ③ 미션 | `미션` | 신호 **해독(복호화)** + 전신키 **응답(암호화)** |
| ④ 전신키 | `전신키` | 길게/짧게 눌러 점·대시 직접 입력 — **추상** |
| ⑤ 카메라 | `카메라` | 빨강·파랑 비즈를 좌→우 인식 + 읽는 과정 가시화 — **반실물** |
| ⑥ 팔찌 | `팔찌` | 확정 배열대로 비즈를 끈에 꿰어 완성(오프라인 안내) — **실물** |
| ⑦ 신호 확인 | `신호확인` | 완성 메시지를 UNO Q LED·부저로 출력 |
| ⑧ 마무리 | `마무리` | 암호화/복호화 개념 1회 정리(학년별) + 기념품 |
| 통계 | `통계` | (보조) 모두가 만든 메시지 시각화 |

> **비즈 색 규칙**: 짧은 **빨강** 비즈 = 점(·), 긴 **파랑** 비즈 = 대시(—)
> **개념 노출**: 활동 중엔 이야기 언어만, 마무리에서 딱 1회 학년별 깊이로 정리.
> **콘텐츠 수정**: 미션 정답·스토리는 `data/stories.js`에서 단어만 고치면 모스는 엔진이 자동 재생성.

## GitHub Pages 배포

1. 이 저장소를 GitHub에 푸시합니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 Source를 `Deploy from a branch`로,
   브랜치를 배포 브랜치, 폴더를 `/booth-app`(또는 루트로 옮긴 경우 `/`)로 지정합니다.
3. 발행된 URL을 부스 모니터의 브라우저에서 전체화면(F11)으로 엽니다.

> 카메라(`getUserMedia`)는 **HTTPS 또는 `localhost`에서만** 동작합니다. GitHub Pages는 HTTPS이므로 OK,
> 로컬 파일(`file://`)에서는 카메라가 막힐 수 있어 아래처럼 로컬 서버로 여는 것을 권장합니다.

## UNO Q에서 실행하는 법

### A) 웹앱만 빠르게 (시뮬레이션 모드)
UNO Q의 Linux 터미널에서:
```bash
cd booth-app
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속 (카메라 권한 허용)
```
하드웨어 브리지가 없으면 ⑤단계는 **화면 LED + 부저 시뮬레이션**으로 자동 동작합니다.

### B) 실물 LED·부저 연동 (Arduino App Lab)
`arduino/` 폴더를 Arduino App Lab 앱으로 실행하면 `python/`은 MPU(Linux),
`sketch/`는 MCU(STM32)에 함께 배포됩니다. 자세한 절차는 [`arduino/README.md`](arduino/README.md) 참고.
- Python 브리지 서버가 `http://localhost:8080`에서 대기 → 웹앱이 자동 감지해 **"UNO Q 연결됨"**으로 전환.
- 연결 실패 시 자동으로 시뮬레이션 폴백.

## 조명 보정 사용법 (③ 카메라)

부스 조명/배경이 바뀌면 **30초 재보정**으로 인식 정확도를 회복합니다.

1. `카메라 인식` 화면에서 **카메라 켜기**.
2. 트레이의 **빨강 비즈**를 화면 가운데(점선 영역)에 크게 보이게 두고 **빨강 보정** 버튼 클릭.
3. **파랑 비즈**로 바꿔 두고 **파랑 보정** 버튼 클릭.
4. 보정 상태 메시지에 기준 색상(Hue)이 표시되면 완료.

> 인식은 **색(HSV의 Hue) 기반**입니다. 길이가 아니라 색으로 점/대시를 구분하므로 밝기 변동에 강합니다.
> 채도(S)로 배경을 제거하고 색상(H)으로 빨강/파랑을 판정한 뒤 **좌→우 순서**로 읽어 모스로 변환합니다.
> 라이트박스로 외부광을 차단하고 촬영조명으로 채도를 확보하면 가장 안정적입니다.

## 디자인 / 브랜드

- GNMC 로고 기반. 로고 심볼에서 추출한 무지개 팔레트를 디자인 토큰으로 사용
  (빨강 `#C00018`, 주황 `#F07818`, 연두 `#78A818`, 파랑 `#1878C0`, 보라 `#784890` 등).
- **기능색과 장식색 분리**: 점=빨강 / 대시=파랑은 비즈 의미와 일치하는 기능색이므로,
  UI 장식에는 주황·연두·보라를 사용해 혼동을 막았습니다.
- 폰트: Pretendard(한글) + IBM Plex Mono(숫자·모스)를 `assets/fonts/`에 **로컬 번들**(외부 요청 없음).
  미설치 환경 대비 시스템 폰트(Noto Sans CJK 등) 폴백도 유지.

> **로고**: 헤더는 `assets/logo/gnmc_logo.png`를 우선 사용하고, 없으면 재현본 `assets/logo/gnmc_logo.svg`로 자동 폴백합니다.
> 원본 PNG를 `assets/logo/gnmc_logo.png`로 저장하면 **코드 수정 없이** 적용됩니다.
> **스토리 삽화**: `assets/story/{k,e,m}/`에 §파일명대로 넣으면 자동 표시, 없으면 “그림 준비 중” 플레이스홀더가 뜹니다(레이아웃 안 깨짐).

## 접근성 / 품질

- 대화면(가로 모니터) 우선, 태블릿 대응 반응형. 큰 글씨·큰 터치 타깃·명확한 대비.

- 전체가 외부 라이브러리 없이 순수 JS — UNO Q에서 인터넷 없이 완전 오프라인 동작.
